> ML 직관을 실시간 인터랙티브 시각화로 가르치는 웹 기반 교육 도구. 1차 사용자는 **교사**, 학생은 수혜자.

## 1. 프로젝트 개요

- **작업명**: 감 / GAM
- **유형**: 웹 기반 인터랙티브 ML 교육 도구
- **목표**: 경사하강법, 과적합/과소적합, 편향-분산 트레이드오프 같은 ML 직관을 실시간 시각화로 체득시키기
- **1차 사용자**: 교사 (학생/독학자 아님). 채택 논리는 "흥미"가 아니라 **위험 회피**
- **최종 목적**: 경진대회 출품 + 포트폴리오 가치 (수익화는 후순위)

## 2. 확정된 핵심 결정사항

- 1차 사용자 = **교사**, 학생은 수혜자
- **로그인·설치 불필요** — 링크만으로 교실에서 실행(link-only)이 핵심 제약
- **시연/프로젝터 모드**는 필수 기능(must-have)
- 학생 관리 기능은 P2(후속 단계)로 유보
- 수익화 후순위 — 대회 출품과 포트폴리오 가치가 우선
- 기술 경로: **Next.js + PWA**가 link-only·무설치 교실 도구에 더 실용적 (Flutter는 비교용으로 프로토타입만 제작)

## 3. 현재 산출물

- **PRD**: `ML교육앱_PRD.md` — 비전·페르소나·차별화·MVP 범위·기술 아키텍처·단계 구분. v0.1 → v0.3까지 3회 개정 (타깃 정의를 두 번 도전·수정하며 §3·§4 대폭 재작성)
- **프로토타입 2종** (둘 다 외부 ML 라이브러리 없이 경사하강법을 from scratch 구현, 실시간 시각화 + 데이터 포인트 조작 + 손실곡선 + 한국어 규칙기반 상태 설명기):
  - React/JSX: `LinearRegressionLab.jsx` (Next.js)
  - Flutter/Dart: `linear_regression_lab.dart` (비교용)

## 4. 타깃 사용자 정의 (핵심 통찰)

- "코드가 장벽인 사람"은 **약한 타깃** — 동기 기반 타기팅보다 **필요 기반 타기팅**이 유효
- 날카로운 프레임: **"교실에서 즉시 시연이 급한 교사"**
- 교사는 기능 개수가 아니라 **마찰·위험 감소** 기준으로 도구를 채택

## 5. 기술 차별화 레이어 (검토 중)

기본 시각화를 넘는 기술적 깊이가 경쟁력의 조건. 후보:
- 브라우저 내 모델 학습 (**TensorFlow.js**)
- 학습 로그 기반 **오개념 진단**(misconception diagnosis)
- 규칙기반 한국어 설명기를 **Claude API** 동적 피드백으로 교체

## 배운 것

- **Flutter vs Next.js 트레이드오프는 실재한다**: Flutter는 네이티브 배포에 적합하나 전면 재작성이 필요하고 API용 백엔드 프록시가 여전히 남는다. 무설치·링크만으로 여는 교실 도구에는 Next.js + PWA가 실용적이었다
- **가장 가치 있는 누락은 기능이 아니라 교실 스크립트다**
